= Proof validation configuration

`proof-validation.k9.ncl` is a K9 SVC component at the `Yard` leash level.
Its Nickel predicates constrain the existing proof targets, required Agda
options, toolchain versions, sibling pins, rejection-control inventories and
explorer correspondence stages. Removing `--safe` from its configured value,
changing a constrained pinned value or deleting an entry from a configured
control inventory causes contract evaluation to fail.

The component is pure configuration. It contains no recipes or imports,
requests no capabilities and grants no network, filesystem-write or subprocess
access. Its script names are data for a separately authorised host to compare
with the checkout. Evaluating the component does not run those scripts and
does not establish that an Agda proof passes.

`hyperpolymath/k9-ecosystem` is the implementation and coordination hub;
the standards repository owns the normative component contract. The
seven-section repository pedigree and the YAML-bodied K9 coordination dialect
are different contracts and do not govern this component.

== Validation and proof evidence

Run the consumer gate from the repository root:

[source,bash]
----
just check-contract
# Equivalent, without Just:
bash scripts/check-contract.sh
# Once the pinned tools are cached, refuse any download:
bash scripts/check-contract.sh --offline
----

The gate uses Bash, the repository's pinned Bun 1.3.14 scripting runtime and
standard Linux command-line tools, including GNU coreutils, grep, sed and awk,
on Linux x86_64. Set `BUN` to the Bun executable when it is not on `PATH`.
The gate downloads
the official Nickel 1.18.0 binary and exactly two
files from the pinned standards commit into ignored `_build/k9-tools/`:
the canonical validator and its normative component contract. Downloads and
every cache reuse are checked against fixed SHA-256 values before execution.
There is no global installation, remote installer execution or dependency on
the full standards checkout. Missing tools, checksum mismatches, timeouts or
skipped semantic checks fail the gate.

The gate applies the canonical contract at strict L2 and exports the evaluated
data. `scripts/check-contract.js` then compares that data with the actual
Just targets, workflow version pins and script invocations, Agda option arrays,
dependency fetch pins, rejection-control inventories and correspondence
stages and table size. Configured command strings are never executed. These
are bounded source-shape checks; they do not establish that the proof scripts
have executed or that their proofs pass.

The helper derives its repository boundary from its own module location.
Its CLI accepts no repository, document, verdict or output paths. Evaluated
data and verdicts come from fixed log filenames, and generated fixtures and
drivers stay in temporary directories under `_build/k9-tools/`. Relative
paths must remain within their selected boundary, and symbolic links in any
existing path segment are rejected before access. The shell checks cache and
log paths through the same helper before opening them.

Three semantic negative controls run with the gate: Nickel must reject a
configured safety-flag omission at `K9-N001` / L2; the checkout comparison must
reject a removed core safety flag; and it must reject a missing core rejection
control. Two additional path controls reject parent traversal and symbolic-link
parents for both reads and writes. Each negative control must fail for its
intended reason. All fixtures are isolated in the ignored cache; the
repository's source files are not changed by these controls. Logs and the
evaluated configuration are written under `_build/check-logs/contract/`.

To invoke the canonical validator directly with an existing toolchain:

[source,bash]
----
bash /path/to/standards/1-formats/k9/tools/k9-validate.sh \
  --strict --layer L2 --json -- contractiles/k9/proof-validation.k9.ncl
----

The validator handles the `K9!` envelope before invoking Nickel. Passing the
whole component directly to `nickel typecheck` is incorrect because the magic
line is not Nickel syntax. Typechecking alone also does not evaluate predicate
contracts; the canonical L2 check both typechecks and exports the value.

Without Nickel, `--layer L1` provides only an envelope and structural screen.
A skipped L2 check is not a successful semantic validation. The unsigned Yard
component does not claim a verified signature or authority to execute code.

The evaluated configuration must be checked against the actual repository
targets. The existing proof scripts then establish their respective results:
`scripts/check.sh`, `scripts/check-siblings.sh` and
`scripts/correspondence.sh`. Verification claims belong in
link:../../PROOF-STATUS.adoc[the proof record], with the hosted run and exact
checked commit required by link:../../docs/GOVERNANCE.adoc[governance].

When a toolchain pin, target or control inventory changes, update this
configuration deliberately and run both the configuration check and the
affected proof checks. The configuration stores expectations rather than a
stale copy of a successful proof receipt.

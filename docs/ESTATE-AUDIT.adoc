== Metrics are observations, not proof verdicts

The same historical estate job emitted three integer-comparison errors in
its metrics step, then printed an unsupported `PROVEN` label. Its use of
per-file `git grep -c` output as a single integer caused the error. It also
reported zero errors for Pons and Panic Attack when their logs were absent.
Neither output is accepted as evidence in this repository's proof record.

The upstream repair reports absent/unreadable logs as not assessed, counts
only marker lines in readable logs, and requires actual prover receipts for
proof claims. Its regression tests include both this repository's merged
tree and an actual Idris repository. It leaves the audit advisory and does
not replace the dedicated Agda proof workflow.

== Informational notices and the separate scanner error

* The original "no K9 files" notice is addressed by the new component and
  its explicit evaluation step.
* The AFFIRMATION governance-tier and BoJ cartridge notices describe
  inapplicability; the repository declares neither requirement.
* The focused secret check's notice correctly limits its scope. It does
  not replace a full-history scanner or GitHub secret scanning.
* The runner migration notice concerns GitHub's moving `ubuntu-latest`
  label. The newer audit uses `ubuntu-24.04`; the proof job already does.
  See https://github.com/actions/runner-images/issues/14748[the runner announcement].

The separate
https://github.com/hyperpolymath/residual-evidence-types/actions/runs/41674256829[Secret Scanner run 41674256829]
did not execute. GitHub rejected its reusable workflow before startup:

----

stayed the same. The selected-actions allow-list lacks that exact workflow.

not reported as a successful scan.

== Supported proof-runner controls

The current suite's `proof-runner-check` supports Idris2 (`*.ipkg`) and Lean
(`lakefile.lean` or `lakefile.toml`). It does not execute Agda or Coq, and the
central estate audit does not invoke this action. The dedicated Agda workflow
therefore remains separate evidence; an absent or unsupported prover is not a
successful proof run.

`.github/workflows/proof-runner-control.yml` installs a checksum-pinned Lean
4.24.0 toolchain and exercises the suite action at the same commit as the
estate caller. A valid Lean fixture must produce `status=passed`. An ill-typed
fixture must make Lake and the action fail with `status=failed`; the enclosing
control job passes only after checking both receipts. A `not_run` result,
missing toolchain, or skipped action cannot satisfy those assertions.

https://github.com/hyperpolymath/residual-evidence-types/actions/runs/42607779570[Run 42607779570]
passed all of these steps. Its intentional annotations record `lake build`
exiting 1 for the ill-typed fixture, while the valid fixture and final receipt
checks passed. This is Lean evidence only, not a claim that the suite executed
this repository's Agda sources.

== Legacy descriptile migration debt

The two legacy descriptiles, `STATE.a2ml` and `ECOSYSTEM.a2ml`, retain their
filenames. Their facts were refreshed on 2026-11-03: contexts, composition,
revision, the finite checker and the 546-configuration explorer correspondence
are implemented, alongside the expanded sibling transports. The recorded
proof evidence is
https://github.com/hyperpolymath/residual-evidence-types/actions/runs/41674253389[run 41674253389],
head `6fe57a2f59347c5feec1a2eb5a1c478f5ef2e095`; it does not establish the
still-open family-or-view decision or the local dependence theorem.

An extension-only rename would produce invalid DEED. The pinned
https://github.com/metadatastician/standards/blob/d3e4b485a2af90c92a8e18af0888cd19cb132cd9/1-formats/deed/spec/abnf/deed.abnf[canonical grammar]
requires S-expressions, `;; SPDX-...` headers, a document head and
`:schema-version`, with filename-based form selection. The existing
`[section]` and `key = value` syntax, and the standalone names `STATE.deed`
and `ECOSYSTEM.deed`, do not meet those rules.

At that same standards revision, the
https://github.com/metadatastician/standards/blob/d3e4b485a2af90c92a8e18af0888cd19cb132cd9/1-formats/deed/mappings/state-v1-decision.adoc[STATE mapping decision]
still requires a ruling on how to separate state from journal history. The
https://github.com/metadatastician/standards/blob/d3e4b485a2af90c92a8e18af0888cd19cb132cd9/1-formats/deed/mappings/meta-ecosystem-to-repo-deed.adoc[ECOSYSTEM mapping]
targets a clause in the repository's `<canonical-name>_chora.deed` and
rejects untabled fields; it does not yet map this repository's custom
`[relationships]` fields. The factual refresh therefore leaves the legacy
format as explicit migration debt.

== Metrics are observations, not proof verdicts

The same historical estate job emitted three integer-comparison errors in
its metrics step, then printed an unsupported `PROVEN` label. Its use of
per-file `git grep -c` output as a single integer caused the error. It also
reported zero errors for Pons and Panic Attack when their logs were absent.
Neither output is accepted as evidence in this repository's proof record.

The upstream repair reports absent/unreadable logs as not assessed, counts
only marker lines in readable logs, and requires actual prover receipts for
proof claims. Its regression tests include both this repository's merged
tree and an actual Idris repository. It leaves the audit advisory and does
not replace the dedicated Agda proof workflow.
